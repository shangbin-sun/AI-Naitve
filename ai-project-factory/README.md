# AI 工作室

## 主智能体与员工子智能体（2026-09-10）

AI 团队定义与任务数据分开存储：`.data/projects/<project_id>/definition/versions/<sha256>` 保存包含员工文件、资料与附件的定义快照。AI 团队助手的实际工作目录和聊天右侧文件入口都是AI 团队根目录；`management` 保存管理元数据。单节点与完整工作流分别归档到 `node-tasks` 和 `workflow-tasks`，内部 task/run/node/attempt 结构一致。

对话右侧的工作空间跟随当前对象：AI 团队聊天查看整个AI 团队；单节点/任务运行及其后续提问查看该次运行根目录，与运行 Codex 的 cwd 一致。可以浏览目录、预览文本和下载文件；接口拒绝跨运行、跨AI 团队及符号链接越界。切换运行会清空旧文件预览。

任务与运行默认展示智能体任务：每个运行有独立 Codex 主会话，使用原生子智能体执行员工节点。平台记录真实子会话、校验依赖与成果路径，支持人工答复、停止和恢复原会话。旧代码任务保留在“代码交付与历史记录”。AI 团队聊天可通过 `run_task` MCP 发起运行，通过 `get_run` 查询。

公共定义修改只影响新的运行，恢复原运行不会刷新快照。运行使用 run 级可写沙箱；子智能体之间按节点目录协作，并非独立操作系统沙箱。默认最多同时执行 4 个任务，每轮主会话超时 1800 秒，可通过 `CODEX_RUN_TIMEOUT_SECONDS` 调整。中断不自动重放。

设计与验收：[产品方案 v0.4](../docs/ai-studio-product-spec-v0.4.md)、[技术设计](reports/code-desk-runtime-architecture.md)、[修改清单](reports/runtime-migration-checklist.md)。真实 CLI 验证可运行 `PYTHONPATH=backend backend/.venv/bin/python scripts/probe_native_runs.py`，另有 `--workflow` 和 `--cancel`；这些测试使用临时数据库，会实际调用本机 Codex。

员工工作流采用“输入 → 横向 AI 协作 → 输出”的静态节点画布，上层展示默认或专业人类支持。点击员工直接进入编辑页面；运行依赖集中在“任务与运行”。详见 [员工协作工作流](reports/employee-workflow.md)。

聊天支持每条最多 4 个附件，每个最大 5 MB。PNG/JPEG/WebP 通过图片通道传入；Markdown、TXT、CSV、JSON 等文档通过快照中的文件路径提供，供 Codex 按需读取。PDF、Word、Excel、ZIP 的上传与归档不等于已成功解析正文；不能声称尚未读取的内容已被理解。文档显示文件卡片，图片显示缩略图。

## 当前聊天架构：持久 Codex 会话（2026-09-09）

普通聊天现在是 Codex 的直接显示窗口。一个常驻 `codex app-server` 管理多个AI 团队，每个AI 团队持久保存独立 `threadId`。每轮追加用户原文、本条附件和简短的AI 团队版本/员工引用，没有重复历史 JSON；详细业务数据通过AI 团队 MCP 按需读取，普通聊天不强制输出 schema；历史与自动压缩由 Codex 管理。已有旧对话首次导入一次，服务重启通过 `thread/resume` 恢复原会话，恢复失败不会静默创建空会话。

聊天框已移除“生成／更新方案”按钮；使用自然语言发起方案修改，“查看方案”保留。旧方案接口仍保留兼容。AI 团队聊天现在也可根据用户明确要求，通过专用 MCP 读取与修改团队和员工、启动真实员工试运行。纯问候或讨论不触发写操作。新界面分别使用 `/api/workspaces/{id}/messages` 和 `/api/workspaces/{id}/plan`；旧 `/api/designs/{id}/messages` 保留原结构化生成兼容语义。

新增两张映射表，原数据保留；Codex 的会话历史同时保存在其本地会话存储。沿用本机登录，不复制凭据。停止仅中断当前轮，退出服务才关闭受管理的进程。AI 团队工具限定当前AI 团队与活动对话，读取和修改复用后端校验；写入带版本条件与幂等记录。其他 MCP 和命令工具保持隔离。

新增能力见 [AI 团队工具与员工优化](reports/project-tools.md)。详见 [持久会话验收](reports/persistent-codex-conversation.md) 和 [当前提示词与实际输入](reports/current-chat-prompt.md)。下文关于逐轮临时调用、普通对话结构化输出的描述属于此前版本记录，聊天行为以本节为准；其他评估和构建任务仍保持原流程。

一个 AI AI 团队工厂，内置员工工程开发能力。当前完成AI 团队筹备阶段：**创建AI 团队 → AI 团队内对话与方案 → 编辑员工 → 保留修订和方案快照**。全局仅“AI 团队”和“员工”两个入口，默认AI 团队，员工入口弱化。

## 启动

需要 Python 3.11+、Node.js 20.19+（或 22.12+）、已安装并登录的 Codex CLI。

```bash
cd ai-project-factory
bash scripts/setup.sh
backend/.venv/bin/python scripts/dev.py
```

打开 http://127.0.0.1:5173。接口文档：http://127.0.0.1:8000/docs。Ctrl+C 停止两个服务。
安装一次后直接运行最后一条命令。可用 `PYTHON=/path/to/python3 bash scripts/setup.sh` 选择 Python。

Codex 连接使用本机 `codex exec`，继承当前系统用户的 CLI 登录状态。生成团队会实际调用模型并消耗账户额度；登录凭据不复制进AI 团队。运行时使用临时目录、只读沙箱、结构化 JSON 输出，忽略个人AI 团队配置，后台持久化任务状态。模型推理使用 Codex 服务；聊天内容和团队草稿会随请求发送。本地数据默认保存在 `.data/factory.db`。

## 当前边界与下一步

这是单机、单用户、单 Python 进程的开发版，仅监听本机。尚未提供身份权限、分布式队列、数据库迁移、云端 VS Code、正式员工评测发布、实际工作流执行、训练或部署。不能直接以多 worker 或公网方式部署。

员工文件当前作为服务端数据库中的虚拟工程持久化，可编辑与导出；尚未挂载为员工运行容器内的真实目录。修改工程不会执行其中代码。AI 团队创建只保存快照，不启动任务。需求试运行会将当前员工工程作为模型输入；参考资料和代码节选也会随设计、评估请求发送给Codex。

`FACTORY_SOURCE_ROOT` 可设置允许导入的资料根目录，默认仓库下的 `AgentAI 团队`。源码导入排除隐藏目录、构建产物和配置文件，仅包含选定源码/文档/Wrapper；不是完整备份。评估保留输入快照，后续资料更新不会改变旧结论。平台只有单用户本地权限边界；请勿对公网开放本机命令执行接口。

下一里程碑：员工试运行沙箱、工具/资源绑定、评测结果和版本发布；然后接AI 团队运行、人工干预及数据交接。产品完整需求位于仓库 `docs/ai-project-factory-product-spec-v0.3.md`，本实现不代表全部需求已完成。

员工产出与工作空间入口通过 `vscode://file/...` 打开本机 VS Code。`python3 scripts/dev.py` 只启动业务后端（8000）和前端（5173），无需独立编辑器服务。本机需安装 VS Code，并允许浏览器唤起应用。

AI 团队助手对话现在通过本机 Codex App Server 的文本增量事件与 SSE 实时显示回复；沿用本机 Codex 登录，无需额外 API Key。开始输出前仍可能等待模型思考。回复正文先显示，完整方案通过校验后才保存；取消、失败或版本冲突不会应用未完成方案。刷新页面或连接恢复时会重放当前回复，已保存消息不会重复。其他评估和构建任务仍沿用原来的调用方式。

性能诊断日志：`.data/chat-performance.jsonl`（每份 5 MB，保留 3 份轮转文件）。按 `job_id` 关联排队、上下文准备、模型进程启动、会话与请求确认、首次模型增量、首段可见回复、正文结束、结构化结果校验、清理、提交数据库和 SSE 首次发送；`job_finished` 汇总阶段时间及解析/数据库写入累计耗时。记录上下文大小、实际模型、推理强度和 token 用量，不记录正文、图片、凭据或原始模型事件。`elapsed_ms` 从后台任务开始计时；SSE 事件通过 UTC 时间与任务关联。SSE 首次发送不等于浏览器实际绘制，重连的首次发送也不代表模型首字延迟。

2026-09-09 提速：AI 团队助手使用独立的会话配置，关闭本机无关技能、插件、MCP、工具目录与AI 团队指令注入；不改全局 Codex 配置，也不删对话历史。默认仍使用原模型和 `medium` 推理；`CODEX_CHAT_REASONING_EFFORT` 可独立覆盖对话强度，`FACTORY_CHAT_LEAN_CONTEXT=0` 可关闭上下文精简用于对照。普通问候、解释无需更新方案时返回 `draft: null`，不修改草稿/员工/版本；明确方案修改仍必须提供完整且通过校验的草稿。

SSE 改为新数据触发推送，回复立即可见；数据库保存第一段并以最多每 200 ms 一次的频率写入检查点，完成/取消/异常时保留最终内容。硬退出时可能丢失最后约 200 ms 的未写入预览，已保存方案不受影响。页面收到结束事件即刷新AI 团队，6 秒轮询只用于恢复同步。

监测：首字超过 10 秒或任务失败/中断会写入 `latency_alert`。页面通过 Beacon 上报首次接收回复及其后显示帧的计时（不含正文；显示帧采样不等同于严格的首次绘制时间）。运行 `backend/.venv/bin/python scripts/chat_latency.py --limit 20` 可读取最近请求的摘要，无需调用模型。日志仅在实际请求发生时追加，不会定时发起模型请求。


### 本机飞书个人账号

AI 团队助手通过 `feishu_desktop` 工具操作服务端 Mac 上登录的飞书，不使用机器人身份。需要本机 Swift 命令行运行环境和辅助功能权限；无权限时工具返回具体授权步骤。支持打开应用、读取可访问性界面、点击实际元素、设置文本及搜索/回车/退出等按键。

发送前须有用户明确的联系人和消息正文，核对当前会话；工具不能把点击或输入成功当作送达证据。每次操作前验证界面版本，操作后重新读取界面；不确定时不自动重复发送。操作范围固定为飞书，无任意脚本或坐标入口。

验证覆盖权限状态、AI 团队与活动会话范围、界面过期、单次操作观察失效及 MCP 参数传递；本机验证打开、搜索入口、中文输入和退出搜索成功，未对外发送测试消息。浏览器访问的AI 团队操作的是服务端 Mac，使用期间应避免同时手动切换飞书界面。

### 自动任务

新建任务保留工作要求与文件上传，提供「定时执行」和「按条件循环执行」：
- 定时支持指定时间执行一次，或每轮完成后按间隔重复；时间输入使用浏览器本机时区。
- 条件循环每轮由模型根据运行摘要、节点验收记录判断停止条件。满足则结束，不满足则等待间隔后再次执行；证据不足、任务异常或需要人工处理则暂停。默认最多 20 次，可调整至 1–1000 次。
- 两者可组合为指定时间开始循环。每轮保留原始输入、创建独立批次、使用启动时的最新配置，并向主 Agent 提供上一轮摘要和来源运行。
- 任务详情可暂停/恢复自动执行；暂停只阻止后续轮次，正在执行的轮次使用「停止执行」单独停止。
- 调度保存在 SQLite 的 task_schedules 表，由本地服务的单进程调度器驱动。关闭浏览器不影响调度；电脑休眠或服务停止期间不会执行，恢复后过期计划补执行一次，不追补积压轮次。执行中断后暂停，避免重复产生副作用。
