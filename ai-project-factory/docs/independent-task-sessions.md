# 独立员工任务会话（方案二）

新建运行标记 `engine=independent-v1`；旧运行保持原生父子执行机制，不静默迁移。
任务编排由应用状态机负责，任务级 Agent 可通过原任务消息入口只读解释与汇总。
每个任务节点拥有独立持久 thread；员工配置不等于会话，同一员工参与不同任务不会共享上下文。

## 五项约束

1. 依赖：只执行前置节点均已成功的节点，缺失或循环依赖停止。串行自动推进。
2. 交接：冻结任务、规则包、节点验收要求；复制附件和上游已发布文件，记录文件哈希、版本、来源和验收记录。
3. 隔离：员工禁用 multi_agent，沙盒仅可写自己的 attempt，不给予团队根写权限；发布文件由服务器复制到独立 deliveries 版本目录。
4. 完成：模型提交 summary、verification、artifacts；服务器检查正式输出和输入哈希后自动完成节点，全部节点成功后自动汇总完成任务。无人工验收门禁；辅助日志与空验证说明不阻断交付。兼容字段 acceptance_record 保存系统输出检查来源，不表示人工验收。
5. 恢复：保留 thread ID、turn ID、工作目录、输入清单、上游版本。重启只标中断，不自动重发。恢复先检查目录及哈希，读取旧 turn；已完成的结果直接复用，状态不明则停止。

## 继续任务聊天

复用任务聊天组件；讨论为只读，不复制修复目录。执行修改恢复同一节点 thread，保留原发布产物，创建新提交；下游原尝试归档并失效，重新验收后才能推进。普通聊天不会更新员工 Workflow 或技能，能力提升另行生成候选并手动保存。

首版不支持在继续聊天时追加附件；有新附件需通过任务输入新建执行版本。历史原生子会话仍走旧入口。应用运行部署为单个服务进程；执行阶段另有 OS 文件锁，防止同一运行重复执行，但不宣称支持多服务写入数据库的完整分布式调度。

## 接口

- `POST .../nodes/{key}/conversation`：content、request_id、mode（discuss/modify）。
- `POST .../nodes/{key}/accept`：已停用，返回410。
- 原 `resume`、`review` 和任务消息接口继续可用，依据 engine 路由。

安全边界测试需区分：模拟模型测试用于验证状态机、参数和恢复；真实模型沙盒检查用于确认文件系统写入限制。自然语言验收由用户完成，不把文件存在检查当作业务质量验收。

官方接口依据：https://learn.chatgpt.com/docs/app-server （thread/start、thread/read、thread/resume、turn/start）。
