# 员工任务聊天时间线

independent-v1 复用 ProjectChat，历史来自原 thread/read(includeTurns=true)，不是由模型重新总结。
公开用户消息和员工回复直接显示，命令、工具、文件变更按原轮次顺序折叠显示；reasoning 不投影。
结构化提交只按字段格式化展示，不生成新事实。未知事件、来源截断或会话压缩明确提示。

前端每次加载20轮，以最早轮次ID向前分页；刷新与已有记录按原生ID去重。
当前兼容实现由服务端读取完整历史后分页，不是原生流式分页；超大记录或读取失败明确报错，不静默截断。
官方接口依据：https://learn.chatgpt.com/docs/app-server （2026-09-17核对）。

任务续聊不再要求选择讨论/修改，默认允许在本节点隔离目录内按用户请求工作。
workspace/outputs 文件清单及哈希未改变时保留原验收；改变后撤销本节点验收并失效下游。
对文件修改后的失败或取消也检查失效。权限、冻结输入和工作目录校验保持不变。
旧版运行仍沿用原恢复机制，不自动迁移为独立会话。

进入独立任务聊天后自动调用 conversation/readiness：只读检查原会话、工作目录、输入哈希、前置版本与冻结快照。
不调用运行 resume，不创建 attempt，不发送 turn。移除手动“核对现场并恢复任务”按钮。
检查成功后直接发送消息；发送时再次核对状态，已中断轮次归档后开始用户的新一轮，已完成但未入库的提交先对账。
无法确认是否送达的消息仍阻止重发。恢复模型执行只发生在用户发送消息后，不在页面打开时发生。

提交校验：验证说明可为空，缺失不阻断交付。误放在 artifacts 中的 logs/ 与 ../logs/ 辅助日志引用单独记录为 submission_notes，不要求文件存在。
如果冻结节点输出或员工 Workflow 必需输出明确包含该日志文件名/路径，则仍检查并登记为交付物。
outputs/ 内声明的交付文件仍要求存在且非空；路径越界与符号链接仍被拒绝。正式输出继续进入待验收，不自动判定业务验收通过。
