# AI 团队组织规则

AI 团队目标、成员和工作流以当前AI 团队定义为准。主 Agent 根据工作流依赖派工，向子 Agent 提供目标、输入、员工规则、技能路径、输出目录和验收条件。
读取AI 团队共享技能，并按任务匹配使用；每个员工同时读取自己的 AGENTS.md 与 instructions.md。员工规则可细化AI 团队规则，不能扩大运行权限。
主 Agent 等待子 Agent 的真实结果，检查产物、验证证据和未解决问题后交接；需要人工决策时记录问题并等待答复。
本文件和AI 团队技能是创建时复制的默认内容，可随本AI 团队独立迭代。规则修改只影响新运行。

## 面向用户的执行总结

执行总结用于让人快速了解执行过程与结果，不是内部日志或思考过程。团队 Agent 的最终回复、员工 Agent 的交付总结以及 finish.summary 均遵循以下规则：

1. 结果：首条直接说明已完成、部分完成、失败或等待用户，并点明具体交付结果；不能用“执行得很好”“已处理”等空泛评价代替事实。
2. 过程：用一句话概括本次实际完成的关键步骤或范围，按先后或因果组织，不逐条复述工具调用。
3. 验证：只列实际检查的方法与结果；未验证就明确说明，不把模型自述当成验收证据。
4. 问题：有失败、错误、遗漏或卡点时，说明原因、已完成部分及下一步；仅在真正需要用户信息或决策时提出具体问题。没有问题时省略此条，不追加确认请求。

用“1.、2.、3.、4.”有序编号，每条一至两句，通常不超过四条，简单任务可少于四条；不为凑格式重复内容。先结果、后依据，简短直接，不输出内部推理、会话标识、工具流水或规则加载过程。
总结不重复列文件名、文件路径或文件清单；输出文件由界面独立展示。每个输出文件另附一至两句文档摘要，介绍实际内容、覆盖范围或关键结论，不以“文本成果文档”等格式说明代替内容摘要。
