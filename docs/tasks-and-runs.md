# 任务与运行

2026-09-08

## 产品结构

项目复用一支团队承接多项任务，例如 Agent1、Agent2。任务保存自身名称、输入说明、验收要求和所选源码快照。每次运行关联到一个任务，并保存启动时的任务、工作流、公共团队和实际执行员工版本。任务更新递增修订号，不改变已启动运行的输入。

项目导航新增“任务与运行”；原“历史”标注为“版本记录”，避免与任务执行历史混淆。原有对话、员工编辑、资料、评估和独立研发入口保留。

## 本版交互

- 创建任务：可暂不选择源码，先保存任务意图；补齐输入后运行。
- 修改任务：版本校验防止旧表单覆盖新输入。
- 同一项目内列出不同任务的状态、当前阶段、运行次数和输入修订。
- 从输入基线运行；选择同一任务已完成/受阻运行的代码版本继续。每轮修复次数 1–4，可停止运行。
- 查看每次运行的冻结输入、团队版本、需求/架构产物、源码补丁、实际测试数和测试报告、执行日志、服务端工作目录；下载完整 JSON 运行记录。
- 地址携带 task 参数，刷新可恢复任务详情。
- 已发送运行具备幂等请求标识，网络重试不重复执行；跨项目源码和跨任务续跑被拒绝。
- 新任务执行保留员工改进方案作为产出，不自动修改共享团队。独立员工设计/构建能力继续沿用现有入口。

## 实现边界

新建 `backend/app/tasks.py`，增加 work_tasks/task_runs 两张表，既有表结构不变。任务运行通过现有 delivery 创建函数调度，与 evaluations 关联；不再实现第二套执行器。任务代码资料只包含选定代码快照，其他非代码资料作为项目公共参考资料冻结。

新增 `frontend/src/tasks` 独立懒加载模块，宿主仅提供项目 ID 和资料入口。运行列表轮询只读取状态等轻量字段，不加载所有运行的正文/源码。接口为项目范围的任务 CRUD 和 runs POST；外部数据接入方可以调用这些接口创建任务并显式启动。本版不包含监听外部消息队列、文件夹或定时自动触发。

执行范围仍为现有 Gradle/JUnit 参考测试驱动的基线检查、需求/架构分析、源码修复和测试验证。不是任意 DAG 执行器；不能指定任意节点跳转。部署未接通，页面明确显示“参考测试通过”而不是“已部署”。同一项目一次只执行一个研发/评估运行，结束后可启动下一项。

数据浏览包括文档、代码片段和报告；任意文件的在线编辑、云端 VS Code、部署产物托管不包含在本次新增入口中。

## 员工产出链（2026-09-08）

任务详情默认展示员工产出链。按照实际运行顺序连接任务输入、基线测试、需求与架构方案、每轮代码开发、测试反馈及续跑复测。每个节点显示负责岗位、接收内容、可展开的交付物、接收方和来源运行。

续跑沿 resume_run_id 追溯同一任务的前序记录，保留历史方案和代码，明确标记沿用成果；复制到本轮的 previous_plan 不视为本轮新产出。其他独立运行通过运行选择器查看，不混入当前链。员工归属依赖运行时冻结的信息，未绑定具体员工的历史记录保留岗位说明；测试进程归属于平台测试执行器，团队中无执行证据的员工不标记已交付。部署仍未接通。

新运行逐轮保存代码产物正文，避免后续补丁覆盖历史。旧记录仅在能确认最终成功轮次时回溯最终产物；缺失正文显示缺失提示，不拿最新版冒充。前序记录缺失会给出提示。

验证：前端 50 项测试通过，后端 53 项测试通过，生产构建通过。浏览器使用 Agent1（70401960fcd64133aa0ce58dcb88e42c）实际两次运行验证 7 个产出环节，展开 build.gradle.kts 确认真实文件正文，核对上一轮及本轮的 247 项测试结果。原测试统计、输入、日志、导出功能保留。

### 展示方式修订：员工优先

根据用户反馈，默认产出页由阶段时间线改为员工分组的产出总览。员工名称作为一级标题，文档正文、开发说明和代码直接显示，同一员工多轮产出归在一起并保留轮次与来源。需求架构结构化数据转换为可读的章节和列表。任务输入不混入员工产出，测试执行器结果单列，完整测试和日志保留在原有详情页。历史无个人绑定仍按岗位说明，不凭当前团队补造归属。

### 文件列表与 VS Code（替代正文平铺）

员工产出页改为紧凑文件列表，仅展示文件名、大小、来源轮次和 VS Code 打开操作；不在任务页平铺文档和代码。服务器按任务校验运行归属后，将保存的文档和逐轮代码产物生成到 `.data/output-workspaces/<run>/`，返回桌面 `vscode://file` 文件或目录入口。编辑副本与原始运行证据分离，重复打开不覆盖人工编辑；人工修改暂不会自动成为下一轮任务输入。

当前入口适用于浏览器和服务端位于同一台机器的本地开发版，已检测到本机 VS Code。尚未部署网页端 VS Code 服务；远程服务器需要另行接入受控的网页工作区，不能直接用本机文件协议打开远程路径。

### 附件卡片样式

每名员工使用紧凑附件卡片：图标和文件名，默认显示三项，“查看全部”展开该员工所有轮次的文件及来源，再次点击可收起。文件名省略时悬停可查看完整名称，点击文件继续使用原有 VS Code 入口；卡片右上角为目录入口。未引入文件上传或伪造加号功能。

### 修复内置浏览器打不开文件夹

默认文件夹与文件入口改为网页内只读文件浏览器，不再通过自定义协议唤起本机应用。按员工展示全部轮次的文件，支持切换正文、保留来源信息、返回附件列表；历史缺正文直接提示。浏览器实测打开需求架构目录、返回及打开 build.gradle.kts 均成功。此浏览器不是网页版 VS Code，也不提供代码编辑保存功能。
