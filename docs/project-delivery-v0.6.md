# 原有样例驱动的项目研发流程 v0.6

## 用户目标与当前执行链路

通过项目聊天输入任务，引用标准资料和原有代码/测试，让平台调用 Codex 形成需求、架构和员工操作规则，自动执行开发与测试，依据真实失败迭代，沉淀员工工程和能力对比。

本轮实现的是 Gradle/JUnit 项目的真实执行适配器，不是任意工具/语言的通用 DAG 执行器。保留原有设计、员工编辑、Python 员工构建及资料功能。

## 已实现

- 项目聊天输入框新增“按原有测试构建并验证”。项目资料页面也可输入目标并启动，任务说明保存在项目对话中。
- 从服务端源码快照冻结原有测试文件及哈希。补齐 YAML/JSON 等资源文件和 Gradle 属性，保持隐藏文件及原有排除项规则。
- 自动准备源码要求的 JDK 17/21：下载官方 Temurin 包、验证 SHA-256、存放平台目录并向 Gradle 显式绑定；离线模式不下载。
- 原始基线 → 平台 Codex 需求/架构分析 → 平台 Codex 开发修复 → 原测试回归 → 逐轮反馈。
- 修复仅允许生产 Java/Kotlin 与 Gradle 配置，拒绝更改参考测试和模块清单；只在副本写入。
- 每轮记录代码版本、变更内容、模型用量、命令、退出码和 JUnit 报告。测试、资源和输出通过平台管理。
- 冻结参考测试哈希，在执行后复核。退出码零仍需有实际测试；跳过、失败及缺失原有测试类均不能通过。
- 运行结束后保存“需求与架构、代码开发、参考测试验证”三个 IT 员工工程，包含 AGENTS、Skill、运行适配器声明、参考测试哈希和评估记录。阻塞的员工明确保留未通过状态。
- 下一轮捕获员工版本及指令，传入平台 Codex 调用。员工更新保留项目修订和运行快照；人工修改导致版本冲突时不覆盖。
- 从指定运行的最后源码版本续跑，保留旧结果。来源新增资源可合入；原源码基线内容改变时拒绝静默复用。
- 对比视图展示原始基线和每轮员工结果，能查看通过、失败、跳过、未执行的测试类及实际日志。

## 能力基准的解释

原有 JUnit 测试体现参考实现要求的部分行为。它们不等于人类全部能力，不代表需求、架构、部署等全部工作的金标准。平台不会从这组测试推断人类耗时、成本或未经覆盖的能力。

通过这些测试只证明符合当前参考断言，不能宣称车辆业务完整验收、真实模型效果、真实设备集成或部署通过。原测试中的 mock/内存替身不会自动升级为真实依赖验证。

## API

- `POST /api/workspaces/{id}/delivery-runs`：goal、max_attempts（1–4，默认2）、offline、可选 resume_run_id。
- `GET /api/workspaces/{id}/evaluations`：冻结输入、方案、迭代、JUnit结果和员工关联。
- `POST /api/evaluations/{id}/cancel`：停止运行、保留证据。
- `POST /api/evaluations/{id}/materialize-workers`：保存员工工程（默认运行结束自动执行，幂等）。

## 存储

- `.data/evidence/{source_id}`：源码与样例快照。
- `.data/checks/{run_id}`：原始基线执行目录。
- `.data/deliveries/{run_id}`：需求架构方案、每轮源码、补丁和测试日志。
- `.data/toolchains`：平台下载且校验过的 JDK。
- 数据库 Evaluation：运行输入、模型输出、过程记录和证据；Employee：当前员工工程；Revision：项目/流程修订。

## 仍需继续建设

- 聊天自动生成并执行任意拓扑的 Workflow；当前执行链路由 Gradle 适配器定义，项目里其他已有流程节点不会被假装执行。
- 将文档、图形、部署和真实外部服务的操作分别接入执行器与验收器。
- 人类文档/输出样例到跨阶段配对测试的完整审核与管理，而非只使用代码原有测试。
- 按业务能力聚合跨运行评分、成本和人工干预指标；当前比较是原测试行为层面的逐轮证据。
- 生产环境容器隔离、资源配额及工具访问控制；当前为本机开发平台的目录副本执行。
