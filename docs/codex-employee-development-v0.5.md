# 模板驱动的 Codex 员工开发与自动评估规范

版本：v0.5｜日期：2026-09-08｜状态：增量产品与开发规范，执行扩展尚未实现。

补充v0.3产品定义与v0.4项目中心体验。保留现有全部功能、工具、数据和编辑方式；全局仍为“项目”和弱化的“员工”两个入口。

## 1. 产品目标与输入

用户通过聊天提供模板流程、模板数据、模板样例和现有工程。平台自动构建项目及员工工程，实际执行每个环节，对照人类预期验证，自动修复并复测，最终输出可追溯评估结果。

| 输入 | 平台需要识别的内容 |
|---|---|
| 模板流程 | 阶段、负责人、依赖、分支、交接、失败处理及人工介入点 |
| 模板数据 | 类型、字段、来源、版本、资源依赖及适用阶段 |
| 人类高质量样例 | 输入与期望输出的配对、适用条件、验收规则 |
| 现有代码/员工/工具 | 可复用能力、版本、运行环境和兼容条件 |
| 运行约束 | 工具授权、部署目标、预算与调优次数上限 |

用户无需手工编写配置。平台生成版本化模板包，展示识别结果与缺口。样例建立case_id→输入版本→人类期望输出→验收规则；无法配对的材料只是参考。链接可访问、正文已摄取、Worker可读取分别记录。

## 2. 基于Codex的员工开发规则

| 组成 | 员工开发方式 | 平台职责 |
|---|---|---|
| AGENTS.md | 工作目标、步骤、工具使用、输出、自检、停止和交接规则 | 编译有效指令、审查冲突、固定版本 |
| Skills | 将绘图、编码、部署等复杂操作组织为可复用技能，可带脚本与参考资料 | 版本、依赖、安装和独立评测 |
| 工具 | Worker实际可用的命令、API、MCP、电脑操作能力 | 资源绑定、授权、就绪检查和调用证据 |
| Codex运行时 | 理解任务、规划、操作工具、修复、交付 | 调度、预算、检查点、暂停与恢复 |
| 产物与事件 | 可观察操作、文件变化、执行结果 | 持久化、哈希、交接及独立验收 |

官方机制：[AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)按目录发现并组合指令；[Skills](https://learn.chatgpt.com/docs/build-skills)支持仓库`.agents/skills`目录。平台必须固定工作目录，记录实际加载来源，不能把员工规则放到不会被发现的兄弟目录。外部资料不能自动升级为员工指令。

拟定员工工程如下；其中workflow.json等由平台解释，不是Codex原生工作流格式：

```text
employee-package/
  AGENTS.md
  .agents/skills/<name>/
    SKILL.md
    scripts/
    references/
  employee.json          # 平台：能力与版本
  workflow.json          # 平台：员工内部流程及失败路径
  contracts/             # 输入、输出及交接契约
  tools/                 # 工具适配及逻辑资源声明
  environment/           # 环境与依赖，不保存明文凭据
  evaluations/cases.json # 公开开发样例
  README.md
```

独立验证答案及评估器保存在评估服务中，不挂载给被测员工。运行目录与员工发布版本分开。旧instructions/role.md、编辑器和ZIP导出继续兼容，由平台同步或编译，避免两份冲突指令。

## 3. 两层执行闭环

项目层：解析模板→创建项目与员工→检查环境→员工独立试运行→项目联调→验收→保存可复用版本。

员工层：接收固定输入→执行内部步骤→操作真实工具→自检→局部修复→独立验收→交接。

绘图员工可以包括理解输入、操作软件、保存原生文件、导出、检查关系与文字、修正。开发员工包括实现、构建、测试、定位与修复；部署员工包括准备、部署、健康检查、失败回滚及复核。员工不能退化为一次提示词调用。

每一步记录输入、操作、输出、成功证据、失败原因和恢复位置。普通可重复操作可自动重试；外部副作用需幂等键、回执查询或恢复策略。恢复会话不等于可以重放外部操作。

项目界面展开员工后展示内部步骤、工具、文件、日志和阻塞。每次尝试单独留存。平台生成run_id、版本、哈希和交接清单，模型不猜测运行事实。工作完成、自检通过、独立验收通过分别记录。

## 4. 运行时与工具接入

保留现有CLI结构化设计能力，新增执行适配器。固定任务可继续使用codex exec；持续会话、事件和人工审批可通过codex app-server本地stdio接入，使用安装版本生成的协议定义。

[App Server官方文档](https://learn.chatgpt.com/docs/app-server)提供双向协议与审批事件，但当前文档及本机CLI仍标记实验性；适配器需要固定版本、兼容验证和CLI回退，不作为稳定生产接口承诺。

Python后台管理调度及Worker。文件型任务使用隔离工作目录或容器；桌面软件任务使用具备软件、会话、许可证及电脑操作适配器的Worker；训练/部署可调用外部作业服务并跟踪状态。当前桌面助手的工具不会自动出现在服务器Codex中。

保留全部工具入口，按员工工作绑定工具与授权。资源缺失时保留部分成果并产生阻塞，不能用模拟结果冒充真实软件操作。

## 5. 自动评估

| 工作产物 | 检查方式 |
|---|---|
| 文档/契约 | 字段、结构、来源、关键要求、未知项与原始材料一致 |
| 代码 | 构建、单元、行为断言、E2E及回归日志 |
| 图形文件 | 原生文件可打开、导出可用、组件关系、文字和布局合格 |
| 部署 | 制品身份、真实启动、健康及业务探测、回滚复核 |
| 训练 | 数据及配置版本、实际作业状态、独立验证集指标、制品可加载 |

先做可确定判定的检查，再由独立评估员工审查语义质量；人类处理标准歧义。评估员工自身需要校准，节点数量、退出码和哈希由程序提供。不能以文件数量、文字相似度或员工自述替代验收。

样例分开发集和独立验证集；不足以分组时标明结论限制。多种合法产出按业务等价性比较，不强制逐字相同。评估标准固定，不允许优化器修改答案换取通过。

报告逐员工、逐阶段、逐样例列出预期、实际、差异、证据、结论、失败归因、成本、时长和版本。保持pass/fail/blocked/not_assessed；关键项未通过不能被平均分掩盖。区分样例范围通过与完整业务验收。

## 6. 自动调优和从指定环节重跑

先判断问题属于资料、工具环境、员工技能/步骤、交接、项目流程还是评估器。产生候选版本，重跑失败用例，再回归原通过用例并独立验证；比较质量、成本和时长，决定保留或回退。

这里的调优主要修改员工工程、技能、工具、内部流程和参数，不等于训练Codex底层模型。达到目标、预算/次数上限、连续无改善或需要业务裁定时停止。

输入、员工、环境、工具或评估器变更均参与影响分析。从最早受影响环节建立新运行，复用需版本匹配且有通过证据；受影响下游失效，旧记录保留。阶段重跑必须由调度器落实，不能只写在员工提示词里。

## 7. 增量实施及兼容

| 现有功能 | 新增能力 |
|---|---|
| 项目聊天、方案、手动编辑 | 模板解析与可执行定义生成 |
| 员工工程、编辑、导出 | 原生指令、技能、工具环境、内部流程和试运行 |
| 来源基线、代码快照 | 样例配对、分组、覆盖范围及资源绑定 |
| 需求试运行、基线测试 | 通用能力入口和真实工具执行，保留独立调用 |
| 独立评估和反馈 | 逐环节自动评估、修复及版本回归 |
| 历史、快照、取消、冲突保护 | 执行尝试、员工步骤及检查点恢复 |

本轮源码核对：runtime.py的现有SYSTEM禁止工具操作且使用只读目录；service.py拒绝全部点目录，因此`.agents/skills`目前不能按上述方式直接导入。应增设ExecutionRuntime和工程物化步骤，对技能路径做精确支持并保留路径穿越防护。现有设计运行保持原用途。本轮只设定规范，没有把这些新增能力标记为已实现。

## 8. 交付顺序与验收主线

1. 聊天导入流程、数据和人类结果，生成可追溯模板包并自动创建项目/员工。
2. 编译员工工程并检查工具环境，真实跑通一个多步骤员工任务，独立验收其产物。
3. 串联项目依赖、交接、人工暂停、失败恢复和阶段重跑。
4. 故意引入一个可检测缺陷，自动定位、修复、复测，并保证原通过用例不退化。
5. 用保留样例验证新版本，展示改进前后证据和未完成项，保存可复用员工与项目模板。

首条主线使用已有Agent资料与代码，选定输入及期望明确的任务逐步贯通。需求、架构、开发、测试、部署是该项目的流程，不能硬编码成平台所有项目必须采用的阶段。绘图、训练等能力依其实际工具环境分别验收。
