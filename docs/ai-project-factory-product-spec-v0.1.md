# AI 项目工厂：产品需求与开发设计文档

版本：v0.1｜日期：2026-09-07｜状态：需求确认稿，尚未作为全部功能的实施承诺

本文用于确认产品需求。已经达成共识的定位作为基线；首版范围、默认策略和具体交互为建议，见第 17 节待确认清单。技术设计用于说明可实施性，接口名称均为平台拟定接口。

## 1. 产品定位

AI 项目工厂（AI Project Factory，`ai-project-factory`）是一个由人类决策与干预、AI 员工执行工作的项目协作平台，内置员工工厂能力。

用户通过浏览器提出目标、组织团队、查看成果、修改资料和处理决策。AI 员工基于 Codex CLI 运行时承担具体任务。平台持有项目状态、协作记录、文件、成果版本与组织记忆，使人员和会话更换后项目仍能延续。

项目可以是调研、数据分析、模型训练、内容生产、运营或软件研发。平台不预设所有项目都经过需求、开发、测试、部署阶段。

### 1.1 已确认的设计基线

- 一个产品内置员工工厂，暂不独立建设第二个平台。
- 后端使用 Python；前端初始选择 React、TypeScript、Vite 和 Ant Design。
- Codex CLI 是初期 AI 员工执行基础，模型推理使用所配置的云端服务。
- 主要计算、文件操作和项目数据管理在服务端完成，用户无需安装本地编辑器。
- 提供浏览器 IDE；项目工作台承担日常协作入口。
- 人和 AI 都是项目成员，沟通围绕项目、任务和成果展开。
- 成果拥有身份和版本，不能仅通过员工文件夹定位。
- 人工修改需要有影响分析、处理状态和生效回执。
- 支持交接、暂停、员工替换、异常恢复及正式验收。
- 记忆更新需要依据，员工会话不是组织知识的唯一保存位置。

### 1.2 目标与边界

核心目标：让人以较少的协调成本，获得可验收的项目成果，同时保留理解、干预和接续工作的能力。

首版不建设通用模型训练平台、独立员工交易市场、复杂公司组织系统，也不承诺所有类型的数据都能在浏览器原生编辑。模型训练项目通过外部作业接口接入；员工能力训练也不等于在平台中直接训练 Codex 底层模型。

“数据沉淀在平台”指业务数据与可观察工作记录由平台持有和管理，不表示云端推理不传输上下文，也不要求保存模型隐藏思考过程。

## 2. 用户、角色与职责

| 角色 | 职责 | 默认权限建议 |
|---|---|---|
| 空间管理员 | 管理成员、运行资源、平台配置 | 管理配置与成员；敏感操作另记审计 |
| 项目负责人 | 设置目标、任用员工、分配授权、最终验收 | 管理本项目与业务决策 |
| 人类参与者 | 执行分配的工作、编辑成果、提供反馈 | 按项目和任务授予 |
| 人类评审者 | 对指定成果评审或验收 | 指定成果读取、评论与评审 |
| AI 项目主管 | 澄清目标、规划工作、处理例外、汇总进展 | 在授权内提出或更新计划 |
| AI 专业员工 | 处理具体任务、交接成果、报告问题 | 仅使用任务需要的工具和资料 |

首版建议采用单组织空间、多项目、多个人类成员；数据结构保留空间 ID，为后续扩展准备。AI 项目主管是特殊岗位的员工，其业务决定同样受平台授权约束。

## 3. 核心对象

| 对象 | 定义及关键关系 |
|---|---|
| 空间 | 项目、成员、员工模板和资源的管理范围 |
| 项目 | 目标、范围、约束、预算、成功标准与当前状态 |
| 员工模板版本 | 岗位职责、技能、工具需求、运行配置、交付约定及评测结果 |
| 项目员工 | 引用固定模板版本，拥有项目身份、权限和工作经历 |
| 团队关系 | 分工、委托、交接、评审和冲突升级关系 |
| 任务 | 目标、输入版本、负责人、依赖、预算和验收条件 |
| 运行 | 某次执行尝试，关联任务、员工、会话、环境及输出 |
| 外部作业 | 训练等长期计算的独立生命周期与服务方 ID |
| 成果及版本 | 稳定成果 ID、不可变版本、文件清单、作者及来源 |
| 消息 | 指定范围内的沟通，关联任务、成果或决策 |
| 决策 | 问题、选项、依据、授权人、选择及生效范围 |
| 变更请求 | 人或 AI 提出的修改及其影响、处理结果 |
| 知识条目 | 带来源、适用范围、版本和验证状态的组织知识 |
| 活动事件 | 可追踪的操作事实，记录操作者、对象、时间和结果 |

一个模板可以创建多个项目员工，一个员工可以承担多个任务，一个任务可以有多次运行。员工、任务和 Codex 会话不能合并成同一个对象。

## 4. 完整业务闭环

1. 人描述目标，上传资料或连接数据源。
2. AI 项目主管提出目标解释、待补资料、团队、工作方案、预算建议和首个交付物。
3. 人调整并确认必要范围和授权；已有授权内的后续常规工作直接执行。
4. 平台创建任务与依赖，任用员工，准备输入快照和工作环境。
5. 员工执行并与其他成员通信；平台记录文件、调用、进展和运行状态。
6. 员工提交成果版本，按项目规则进入自动检查、同行评审或人工验收。
7. 人提出意见或直接修改，平台形成新版本并计算对后续工作的影响。
8. 平台按授权调整任务，给出变更生效回执；发生异常时恢复或更换员工。
9. 达到项目验收条件后由授权人结项，整理成果、决策与有效经验。
10. 按资源策略停止运行、释放临时环境，保留可导出与可重新打开的项目记录。

## 5. 功能需求

### 5.1 项目创建与管理

- 支持自然语言创建项目；结构化维护目标、范围外事项、期限、预算及成功标准。
- 目标模糊时，提出假设和低成本验证步骤；明确区分已确认事实与待验证假设。
- 支持创建空项目和使用项目模板；首版项目模板可后置。
- 支持阶段目标和里程碑；无需套用统一行业流程。
- 项目变更保留版本和决策来源，不能覆盖历史依据。
- 状态：草稿、进行中、暂停、待结项、已完成、已取消、已归档。
- 归档是可恢复的数据组织操作；删除采用单独的数据生命周期策略。

### 5.2 内置员工工厂／员工中心

- 创建员工模板：岗位、能力边界、工作指令、技能、工具需求、输入输出约定。
- 配置兼容的模型与运行参数，引用执行环境镜像及依赖。
- 支持隔离试运行，用样例任务和明确标准评测；显示结果、成本和失败案例。
- 模板状态：草稿、已发布、已停用。发布版本不可原地覆盖。
- 任用时固定版本，配置项目岗位、权限和知识访问范围。
- 支持暂停、替换、退出和升级；升级需通过检查并明确受影响任务。
- 在岗经验归平台保存，提炼为通用模板改进前需验证及相应授权。
- 首版以人工比较评测结果为主，不实现自动晋级或自动训练底层模型。

### 5.3 团队与协作

- 支持一项任务有一个最终责任人和多个协作者。
- 支持并行分工、顺序交接、委托、评审、专题讨论。
- 委托检查权限、资源与任务范围；员工不能自行无限扩大团队。
- 交接记录成果版本、说明和必要输入；接收者可以接受或退回。
- 首版使用列表配置团队关系，关系图作为查看能力可后置。
- 讨论有责任人、结束条件和预算；无法解决的冲突升级给指定负责人。
- 依赖图禁止形成无法执行的循环。迭代工作通过新一轮任务明确表达。

### 5.4 工作规划与任务调度

- 支持人手动创建任务、AI 提出任务和按预设规则生成任务。
- 任务可以分配给人或 AI；人类任务通过待办和成果提交推进。
- 每项任务包含目标、输入版本、负责人、优先级、依赖、交付约定和验收方式。
- Python 调度服务按依赖、权限、预算和可用容量启动工作。
- 常规状态变化由程序处理；需要判断、重新规划或处理例外时唤醒 AI 主管。
- 等待人工或外部作业时，不要求模型保持持续推理。
- 提供暂停、取消、重试、重新分配和从有效成果继续的入口。
- 重试记录新的运行，不覆盖之前失败事实。

### 5.5 协作通信中心

- 项目讨论区、任务／成果讨论区、个人待办与通知中心。
- 支持 @ 成员、回复、附件引用、关联成果版本和问题线程。
- 消息类型包括讨论、询问、委托、交接、评审、决策和阻塞报告。
- 普通讨论不自动修改任务状态；执行性指令需要解析、权限检查和回执。
- 状态至少区分已送达、已接收处理、已完成、已拒绝。
- 只有需要处理的消息触发 AI 执行，防止通知引发无限回复。
- 未响应事项按项目策略提醒或升级；通知可合并、订阅和静音。
- 消息只在有权范围内投递；大文件通过受控版本引用传递。

### 5.6 人类决策与干预

- 决策请求包含问题、证据、选项、推荐方案、成本／时间影响和阻塞范围。
- 区分业务决策和运行权限审批，批准前者不等于扩大后者。
- 人可以修改目标、调整优先级、反馈成果、接管编辑、暂停任务和替换员工。
- 变更先保存为草稿或正式提交；提交后展示影响分析。
- 影响对象包括待执行任务、正在运行任务、待验收成果及已验收成果。
- 每个影响对象有明确处置：继续、暂停、重新运行、重新验收或保留原结果。
- 显示生效回执：哪些已更新、哪些仍等待处理、失败原因是什么。
- 人工决策过期、输入版本已变化时，提示重新检查，禁止悄悄应用旧批准。
- 暂停状态需区分请求已发出、运行已停止和外部作业仍在运行。

### 5.7 云工作空间与编辑

- 提供文件树、搜索、上传、下载、预览和打开编辑器。
- 浏览器 IDE 访问服务端受控工作目录，首版具体实现需做兼容性验证。
- 文本、代码和配置支持浏览器编辑；其他类型支持预览、下载修改后上传。
- 员工使用独立任务工作目录，正式成果以版本清单提交。
- 原始输入默认保留，修改生成新版本；共享内容不能由任意员工直接覆盖。
- 人可接管工作副本，平台暂停相应写入；同时修改通过副本和冲突处理完成。
- 首版不实现字符级多人实时协同编辑。
- 文件保存不等于业务提交；页面需提示未提交修改。
- IDE 的终端同样受环境权限限制，不能绕过项目权限访问宿主机或其他项目。

建议逻辑目录：

```text
/projects/{project_id}/
  inputs/                              原始输入
  shared/                              已发布共享资料的访问视图
  employees/{employee_id}/tasks/{id}/  员工工作副本
  deliverables/{artifact_id}/          正式成果访问视图
  feedback/                            反馈附件
```

目录只是访问视图。数据库保存身份、关系和状态；对象存储保存不可变文件版本；大型数据可通过专用存储或挂载访问。

### 5.8 成果、数据关系与验收

- 成果类型支持文档、代码、数据集、模型、图片、报告及外部结果引用。
- 每个版本记录文件清单／哈希、来源任务、作者、输入版本和生成配置。
- 记录产出、派生、使用、版本及验收关系，支持影响追踪。
- 下游绑定确定的输入版本，不自动跟随“最新文件”。
- 验收规则可组合自动检查、AI 评审和人类验收。
- 评审失败退回修改，保留原版和理由；验收通过不代表永久适用于新目标。
- 成果被新变更影响后标记需要检查，不删除原验收记录。
- 任务完成需要验收证据；Codex 一轮回复结束仅代表本轮运行结束。

### 5.9 资源、运行与外部作业

- 管理执行环境、工具连接、数据源、模型认证引用及资源配额。
- Codex Runtime 运行在独立 Worker 环境，避免长期任务占用 Web 请求。
- 训练等长作业独立保存提供方 ID、状态、配置、产物和取消结果。
- 停止 Codex 会话不自动视为取消外部作业。
- 支持运行日志、心跳、超时、取消及失败分类。
- 区分模型错误、工具错误、环境故障、缺少资料、权限拒绝和业务不满足。
- 限制任务／项目预算与无有效进展的循环次数；达到边界后形成明确待办。
- 调用成本无法精确获取时标记估算或不可用，不能显示为零。

### 5.10 组织知识与改进

- 保存项目事实、规范、决策、经验及适用范围。
- 知识状态：待验证、有效、已替代、已废弃。
- 加载上下文时按任务相关性和权限选择资料，保留引用版本。
- 员工提出知识更新建议，按规则验证后生效。
- 同类错误和返工记录可用于改进模板，首版不自动扩大员工权限。
- 跨项目共享通过明确发布完成，避免项目私有资料被自动复用。

### 5.11 项目看板、导出与结项

- 首页展示目标、阶段进度、最新成果、当前活动、阻塞和待处理事项。
- 显示最近一次访问以来的关键变化，支持展开完整时间线。
- 进度基于任务和里程碑事实；探索性工作不伪造精确完成百分比。
- 提供时间、成本、验收通过率、人工介入和返工统计。
- 结项生成成果目录、验收依据、遗留问题和经验建议。
- 支持导出清单及可访问文件；未包含的外部大文件明确列出原因和引用。
- 首版提供服务端备份恢复流程；跨平台一键导入后置。

## 7. 状态与一致性规则

### 7.1 任务状态

待开始 → 执行中 → 待验收 → 已完成。

另有等待决策、依赖阻塞、执行失败、已暂停、已取消。等待状态必须保存原因、责任人和恢复条件。验收退回可回到待开始；原成果与运行保留。

### 7.2 运行与任务分别管理

运行状态：排队、启动、运行中、等待输入、结束、失败、取消。

一次运行结束可能仍有后续工作。会话异常也不意味着已提交成果失效。恢复操作先检查有效成果和外部操作，再决定继续或创建新运行。

### 7.3 一致性约束

- 一个任务同时只有一个有效主执行租约；超时失效的 Worker 不能提交新正式结果。
- 消息和工具请求通过唯一 ID 去重，数据库提交和事件投递保持可恢复的一致关系。
- 不宣称外部操作能够天然“恰好一次”；重试前核查其实际结果。
- 成果版本不可变，使用新版本需明确记录。
- 并发修改使用版本检查，过期更新返回冲突而非覆盖。
- UI 断线后从已保存的事件继续读取，避免丢失完成或审批状态。

## 8. Codex 接入设计

采用自建执行环境，由 Python Worker 通过 Codex SDK／app-server 控制 Codex CLI 运行时。模型推理由配置的云端服务提供，当前桌面客户端不作为生产依赖。

Codex 项目主管负责需要判断的规划工作；Python 服务负责权限、调度、一致性和资源限制。平台数据库是项目事实来源。

定义 `CodexRuntimeAdapter`，隔离启动、继续、事件消费、中断和恢复等版本差异。具体能力必须在锁定版本上实测，不能直接假定桌面客户端的插件、工具或历史均能复用。

平台工具示例：`get_project_context`、`create_task`、`send_message`、`submit_artifact`、`request_review`、`request_decision`、`report_blocker`、`propose_memory`。这些是拟建业务工具，不是 Codex 原生 API。

每次调用由服务端绑定空间、项目、员工和运行身份。角色指令用于指导行为，实际权限由后端、文件系统和运行环境强制执行。

长时间无输入时释放运行资源，后续事件触发继续。会话无法恢复时，从平台快照和交接资料启动新会话；已有外部作业单独恢复关联。

官方接入依据（此前已核对，实施时再次核实锁定版本）：

- Python SDK：https://learn.chatgpt.com/docs/codex-sdk
- app-server：https://learn.chatgpt.com/docs/app-server

官方文档对部分 app-server／WebSocket 能力标有实验性限制；首版优先封装服务端本地通信，前端仅连接平台 API。

## 9. 数据与技术架构

- 前端：React + TypeScript + Vite + Ant Design。
- Web 服务：Python + FastAPI，模块化单体。
- 执行层：独立 Python Worker、Codex 适配层和受控执行环境。
- 数据库：PostgreSQL，存储业务对象、状态、版本元数据、事件和审计。
- 文件层：持久工作卷与 S3 兼容对象存储，分别承载可编辑副本和成果版本。
- 事件展示：前端以 SSE 接收更新；双向终端通信通过受控连接实现。
- 异步任务：采用持久任务机制，具体队列产品在技术验证后确定。
- 浏览器 IDE：独立服务、统一身份入口、项目范围访问；具体实现待兼容性验证。

初期模块：identity、projects、employees、tasks、communications、decisions、artifacts、workspace、runtime、knowledge、audit。

认证信息通过密钥引用使用，不能放入员工模板、提示词、普通日志或导出包。模型服务账号和计费按部署环境配置，不能假定个人桌面登录可直接作为多用户生产服务认证方案。

## 10. 授权与数据生命周期

默认策略建议：员工可读取授权输入、修改自己的任务工作区、提交成果；不能直接覆盖已发布成果或自行扩大权限。

授权可按项目、员工、工具、环境和操作类型配置。重大范围变更、超预算及没有事先授权的外部操作进入决策或审批；日常已授权工作直接推进。

保留工作相关操作、消息、工具结果、文件变化、审批和验收记录。大输出允许截断展示但保留可访问原件或明确存储策略；敏感值先脱敏。

归档不删除数据。删除、保留期限、备份周期、恢复目标与空间配额需在正式部署前确定。退出项目的员工或人失去访问权限，其已归属项目的成果继续保留。

## 11. 首版范围建议

### P0：首版必须形成闭环

- 单空间、多项目、基本人类成员与权限。
- 创建项目，明确目标、输入及验收标准。
- 员工模板、简单试运行、版本发布和项目任用。
- 一个 AI 主管与可配置专业员工，支持人类任务。
- 任务依赖、运行管理、交接、消息和决策待办。
- 文件上传预览、云端文本编辑、成果版本与人工验收。
- 人工变更、逐项影响处置和生效回执。
- 暂停、重试、员工替换和中断恢复。
- 项目知识、可追踪活动、基础成本与预算限制。
- 项目结项、导出清单、备份恢复流程。

首版影响分析可由 AI 提议、人在必要时确认，不要求自动理解任意文件内容的全部依赖。

### P1：闭环稳定后扩展

- 项目与协作模板、团队关系图。
- 大型数据集、模型产物的专用预览与对比。
- 标准化外部训练作业适配器。
- 更完整的自动评测、通知策略、经验提炼和跨项目共享。
- 高级权限、成本分析及跨项目资源调度。

### 暂不纳入

独立员工市场、完整模型训练基础设施、自动员工晋级、通用字符级协同编辑、跨平台一键迁移、完全无人监督的任意外部业务执行。

## 12. 验收场景

| 编号 | 场景 | 通过条件 |
|---|---|---|
| A01 | 模糊目标创建 | 形成可编辑方案，明确假设、缺少资料和首个成果 |
| A02 | 员工任用 | 固定模板版本，实际工具和目录权限与配置一致 |
| A03 | 员工协作 | 上游提交具体版本，下游接受或退回，责任归属可查 |
| A04 | 人类参与 | 人类收到任务并提交成果，后续 AI 工作正确启动 |
| A05 | 修改反馈 | 人提交新版本，平台列出影响并显示实际生效情况 |
| A06 | 并发编辑 | 人接管时不会被 AI 覆盖，冲突可发现和处理 |
| A07 | 员工替换 | 替换后可使用已保存状态继续，原员工不能继续提交 |
| A08 | 故障恢复 | Worker 中断后任务可恢复，不重复产生已确认的外部操作 |
| A09 | 预算与循环 | 到达配置阈值停止新增执行，展示原因和处理入口 |
| A10 | 验收结束 | 有验收证据才完成，结项后按规则释放资源 |
| A11 | 数据归属 | 退出成员失去权限，项目仍保留完整成果与来源 |
| A12 | 通知断线 | 浏览器重新连接后能获得遗漏状态，消息不会重复执行 |
| A13 | 长作业适配验证 | 使用测试作业验证会话中断不丢失作业、取消结果独立显示 |
| A14 | 备份恢复 | 在测试环境恢复项目元数据和对应成果版本，关联一致 |

首版主验收案例建议采用数据分析项目：准备输入 → 分析 → 评审 → 人修改 → 重做受影响部分 → 替换员工 → 恢复 → 验收。训练作业使用适配器测试场景验证生命周期，避免首版依赖完整 GPU 平台。

## 13. 质量和非功能要求

- 隔离：权限检查覆盖 API、消息、文件、IDE 和工具执行。
- 可恢复：重启服务后，持久任务、成果和待办仍可追踪。
- 可解释：用户能看到决策依据、数据来源和可观察操作结果。
- 可用性：模型等待、工具等待、缺少输入及系统失败具有不同展示。
- 可测试：调度与权限可通过模拟员工测试；另有真实 Codex 集成验证。
- 性能：业务接口与模型运行分离，长任务不阻塞工作台。
- 容量：上线前明确并发员工数、文件大小、运行时长和空间配额，并执行对应负载测试。
- 性能时延、可用性及备份恢复的数值目标，在部署规模确认后制定，本文不把未测试指标作为承诺。

## 14. 产品效果指标

以相似任务的人工基线比较，分别记录质量、时间和成本，不只统计模型输出量。

- 成果首次验收通过率与最终通过率。
- 人工投入时间：解释、确认、检查、修订和故障处理。
- 项目／任务交付周期及等待时间。
- 变更反馈到实际生效的时间。
- 员工替换和故障恢复成功率。
- 同类错误复发率、重复工作量。
- 实际模型与计算成本；缺失数据单独标记。

首个试点先建立基线，再确定扩展门槛，不以预设“自动化率”代替业务价值。

## 15. 实施顺序与阶段出口

1. 接入验证：Python 控制 Codex，验证事件、文件、工具、中断和认证方式。出口：可重复运行的集成验证。
2. 单员工闭环：创建任务、执行、提交成果、人验收。出口：状态和文件版本一致。
3. 团队闭环：模板任用、主管规划、依赖、消息、交接。出口：完成非软件研发场景。
4. 人工干预：编辑、反馈、影响分析和生效回执。出口：变更正确影响后续任务。
5. 可靠性：暂停、恢复、替换、预算、权限及备份。出口：A01—A14 相关首版场景通过。

以上为顺序建议，开发工期在接口验证与页面范围确定后估算。

## 16. 主要风险与处理方向

| 风险 | 处理方向 |
|---|---|
| 模型把猜测当事实 | 显式假设、来源引用、验收与知识验证 |
| 员工无限讨论或反复重做 | 预算、讨论结束条件、主管升级与人工决策 |
| 多人／多员工覆盖文件 | 工作副本、不可变版本、写入租约和冲突检查 |
| 一条自然语言消息被误当授权 | 结构化动作、权限检查、清晰回执 |
| CLI 升级破坏集成 | 固定版本、适配层、升级验证与回退 |
| 项目依赖长期单一会话 | 平台持久状态、交接资料和新会话重建 |
| IDE 与工具绕过权限 | 环境隔离和统一凭据边界 |
| 长任务停止不彻底 | 外部作业单独跟踪，停止状态明确区分 |

## 17. 本轮需要确认的产品选择

以下为建议默认值，尚未视为用户已批准：

| 选择 | 建议默认值 | 影响 |
|---|---|---|
| 首版用户范围 | 自己团队使用，单组织空间、多用户、多项目 | 决定认证及组织复杂度 |
| 项目主管 | 每个项目默认配置一名，可暂停自动规划 | 决定日常协调入口 |

| 员工建立方式 | 模板配置、试运行、发布后任用 | 暂不建设训练底层模型功能 |
| 人类成员 | 可以承担任务和交付成果 | 支持真正的人机混合团队 |
| 编辑协作 | 预览／评论／直接编辑，首版不做字符级协同 | 决定编辑器集成范围 |
