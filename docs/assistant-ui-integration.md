# assistant-ui 项目对话接入

2026-09-08

## 边界与结构

- `frontend/src/chat/ProjectChat.tsx` 使用 assistant-ui ExternalStoreRuntime、Thread、Message、Composer primitives；通过消息、运行状态和 send/cancel/build 回调接入宿主。聊天模块不知道员工和工作流的数据写入细节。
- `frontend/src/chat/attachments.ts` 独立封装图片上传、删除、发送适配器；`chat.css` 样式均带 factory-chat 前缀；组件按需加载，新增聊天包约 422 KB / gzip 128 KB。
- App 继续负责项目路由、轮询刷新、请求幂等 ID、版本校验和构建入口。保留待确认问题填入对话、首次创建失败恢复、方案/历史/资料评估/员工编辑。
- `backend/app/chat_attachments.py` 独立保存附件并校验图片类型、尺寸、项目归属及消息绑定。增加独立表，不修改既有表结构，也不复制旧项目/员工数据。
- 现有 CodexRuntime 仅增加图片输入；原有结构化设计、员工构建和交付流程保留。本次没有把员工执行器整体迁移到 App Server，也没有宣称具备完整 Codex 桌面客户端的终端、审批、工具流式展示。

## 使用

进入项目 → 对话，可输入文字、使用“添加图片”或粘贴截图；支持预览、发送前移除、只发送图片。历史文字与图片保存在服务端，刷新后恢复。Enter 发送，Shift+Enter 换行，兼容中文输入法；运行时显示真实阶段状态并支持停止。补充要求通过已有设计接口更新当前版本，并保留版本冲突保护。

每条最多 4 张图片；单张 PNG/JPEG/WebP 最大 5 MB、2500 万像素。最近 30 条消息中的最新 12 张图片传给 Codex，更早图片保留在对话历史。附件携带 message_id 与对应消息关联，二进制不会写入文字提示词。未发送且未移除的上传图片会保留在服务端，目前不自动清理。

“按原有测试构建并验证”继续使用原有交付接口；有待发送图片时，需要先发送图片完善方案，再输入构建要求。图片之外的文档资料沿用“资料与评估”入口。
