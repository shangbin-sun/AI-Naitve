# 任务运行节点与工作副本续跑

入口：项目 → 任务与运行 → 选择任务和运行 → 员工工作流程。

运行图按当前真实执行器显示：输入与基线测试 → 需求与架构 → 开发 → 参考测试。部署显示未接入。它不把设计草稿中的任意步骤伪装为已接通的执行节点。

- 每 4 秒读取该任务运行的节点状态与已有工作副本的内容摘要。
- 基线直接通过时，分析和开发标为本轮无需执行；已有方案标为复用。
- 修改已有员工 `workspace` 内的方案或源码副本，会显示已修改，并标注下游需重新验证。
- Run · 重新分析：重新调用平台 Codex 分析，然后进入开发和测试。
- Run · 从开发继续：采用当前方案（必须存在），调用开发员工并继续测试。
- Run · 仅测试：验证当前代码；失败即保留失败结果，不调用开发员工。
- 方案修改应从开发继续，不能用单独测试声称新需求已验证。

每次 Run 创建独立运行，保存任务与员工修订、来源运行、修改内容及 SHA-256 摘要。执行只写隔离代码副本，历史数据库产物与源码快照保持不变。提交时修改摘要不同返回 409；重复请求返回原运行；跨任务续跑拒绝；项目执行中拒绝另一轮并发运行。失败、停止或中断记录可从可用的最后代码副本重试，缺少副本时从原始源码开始。

边界：当前采用的是已生成的 `workspace` 文件修改，新增文件与平台整理的 `outputs/process/evaluations` 归档不作为输入；参考测试和模块清单不允许被修改；尚不支持任意 DAG 调度与自动部署。员工目录仍可通过网页版 VS Code 打开。

实现隔离：`backend/app/run_flow.py` 负责证据投影和编辑内容快照；既有 `tasks.py` 只增加任务范围的查询及参数；`delivery.py` 复用隔离执行流程；前端节点组件独立于员工文件列表和聊天。

验收项目：员工流程可视化与运行管理（5bf1842599b8468697f1ba5510eed250）。测试任务和真实运行结果以平台记录为准，自动化测试中的模拟执行不计入真实 Agent 验收结果。
