## 已复现并修复

1. **有未保存修改时，员工抽屉关闭按钮无响应。** 在用户的 Chrome 页面复现；控制台提示 Ant Design 5 与 React 19 兼容性及静态 Modal 上下文问题。改为 `AntApp.useApp().modal.confirm`，并在应用入口添加官方 React 19 兼容补丁。真实浏览器验证确认框出现、继续编辑保留输入、确认丢弃关闭。
2. **项目快照中的问题按钮无动作。** 快照不提供回答回调，现在展示为只读文字；成员卡片同样使用只读容器，避免显示不可点击按钮。
3. **人类岗位卡片仅提示无法编辑。** 现在点击后打开团队方案编辑，支持调整人类职责。
4. **新增文件路径无效，直到保存才报错。** 新增阶段即拒绝绝对路径、上级目录、隐藏路径、反斜杠及保留文件名；处理首尾空格并检查重名。

兼容性依据：[Ant Design 官方 React 19 说明](https://5x.ant.design/docs/react/v5-for-19/)。

## 2026-09-07 项目详情体验修正（取代前述只读卡片处理）

用户指出将项目员工卡片改为不可点击展示并未满足查看详情的需求。原测试只断言“没有无效按钮”，遗漏了“从项目进入员工并继续操作”的业务路径。

现在项目卡片可打开员工详情，展示完整职责、输入输出、技能、指令、团队和员工版本；AI 员工可查看、切换并下载该项目保存的工程文件。详情和项目主页均提供“前往团队编辑”；项目待确认问题可返回原团队并填入聊天框；工作流负责人可直接打开员工详情。

新增快照工程下载接口明确读取 Project.snapshot，不读取当前员工文件。后端测试覆盖原员工更新后下载仍保留旧版本，以及非项目成员的下载请求返回 404。

验证：16 项前端交互测试、22 项后端测试通过；真实 Chrome 中从“交互回归验证团队”打开“回归测试分析师”，查看工程文件、触发真实下载，并返回原团队编辑成功。生产构建通过。

仍存在的产品范围缺口：资源实际绑定、项目内独立编辑/升级快照、员工执行、自动工作流和部署尚未实现。本次修复完成的是项目详情查看与返回编辑路径，不能把它称作全部业务已闭环。
