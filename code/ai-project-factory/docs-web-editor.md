# 网页版 VS Code

本地单人版本通过独立的 code-server 服务编辑服务器工作副本。员工卡片的文件夹和文件入口打开真实 IDE；“只读预览”仍可查看原始运行证据。

## 启动

macOS 安装：`brew install code-server`。

- `python3 scripts/dev.py` 同时启动后端、前端、编辑器。
- 已运行前后端时，用 `python3 scripts/editor.py` 单独启动编辑器。
- 编辑器默认监听 `http://127.0.0.1:8787`，配置和用户设置位于 `.data/web-editor/`。
- 运行目录和文件均由后端根据任务、运行、环节确定，客户端不传任意磁盘路径。

## 数据

编辑目录为 `.data/output-workspaces/<运行>/<环节>/files/`，保留代码相对路径。历史文档和代码被复制为可编辑文件，重复打开不覆盖已有编辑；旧版本生成的工作副本会保留并迁移。平台只读预览仍展示数据库中的历史产出，而不是人工编辑后的副本。

此版本支持打开、编辑、保存，尚未自动把编辑副本设为下一轮任务输入。现有任务的运行输入规则保持原样。

## 部署边界

默认配置仅用于本机单用户，不对外开放监听，未实现多用户工作区隔离。编辑器的目录入口是导航范围，不是操作系统权限边界。远程部署应使用身份认证、HTTPS 和独立用户/容器工作区。

后台可设置 `FACTORY_WEB_EDITOR_URL` 为浏览器可达的编辑器地址，`FACTORY_WEB_EDITOR_HEALTH_URL` 指定内部健康检查地址。用户无需安装桌面 VS Code；服务端仍须安装 code-server。

官方接入资料：https://coder.com/docs/code-server/FAQ

## 本次验证

安装版本 code-server 4.112.0。前端 57 项、后端 56 项测试通过，生产构建通过。实际从员工卡片打开工作目录和中文文件，在浏览器中新建验证文件并保存，检查服务器正文及刷新后持久化；验证文件已清理，原方案与运行记录一致。内置浏览器采用兼容的 textarea 输入模式。编辑器首次打开目录可能提示工作区信任；只查看和编辑文档可继续使用受限模式。

本机环境兼容记录：Homebrew 安装更新 simdjson 后，旧 Node 25 仍依赖 libsimdjson.29。保留旧版 4.2.4 的真实动态库，并在 4.6.11/lib 下添加同名兼容链接（不将新版库伪装为旧 ABI）；已验证原 node/npm 命令恢复正常。平台启动脚本在本机优先使用随编辑器安装的 Node 22，避免依赖原有 Node 版本。

## 员工过程数据归档（更新目录规则）

编辑器现在打开 `.data/output-workspaces/<run>/employees/<employee-role>/`，替代此前仅打开环节 files 目录的方式：

- `employee.json`：运行时员工身份、版本；历史未绑定时明确记录按岗位归档。
- `inputs/run-context.json`：任务输入、资料及团队冻结信息。
- `outputs/`：原始方案、补丁及用量等已有输出证据。
- `process/calls.json`：新运行每次员工调用的输入、指令、输出契约、模型配置、输出、日志、用量、时间及状态。历史未保存的数据不补造。
- `process/shared-workflow.log`：明确标为公共的流程日志，方便在员工目录直接阅读。
- `evaluations/`：实际测试反馈。平台测试执行器目录另包含完整原始 baseline.log 和可找到的 JUnit XML。
- `workspace/<环节>/`：可编辑副本，保留多轮文件以及已有人工修改。

运行级公共数据同时保留于 `<run>/shared/`。导出的输入、过程和评估档案由平台同步，人工编辑应放在 workspace 中；原始数据库证据仍是事实来源。员工执行中的数据会随平台保存点持续归档，完成/失败/取消时同步最终状态。`python scripts/archive_outputs.py` 使用同一个归档器补齐已有交付运行。

覆盖范围为当前交付流水线。其他独立员工构建/试运行功能原有数据目录继续保留；没有执行的部署不会产生虚构的部署记录。原始大型源码快照仍保留在平台共享存储，由输入记录追溯，不重复复制到每个员工目录。

## 文件真实性与清单一致性

员工卡片现在读取后端扫描的实际目录清单，展示 VS Code 根目录下的相对路径、字节数、来源运行和 SHA-256。档案索引区分平台整理的运行归档、从原始产物生成的可编辑副本、人工或工具新增的工作区文件；工作副本与原始产物不一致时标记已修改。点击条目使用同一个清单解析精确路径，不再用旧产物显示名猜文件位置；“刷新目录”可获取 VS Code 新增或修改的文件。

已核对样例：outputs/plan.json 中的 plan、workspace 中方案 JSON、evaluations/baseline.json 分别与原运行 plan、工作副本初始内容、attempt 0 一致。历史 calls.json 为空表示缺少当时的个人调用记录。README 和包装结构由平台生成，不能当作员工独立产出。当前样例分析员工 9 个文件的页面清单与磁盘逐项一致。
